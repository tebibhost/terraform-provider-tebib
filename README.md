# terraform-provider-tebib

The TebibHost provider for Terraform and OpenTofu (Phase 7, ADR 0042). It manages resources
through the public API (`/api/v1` on `cloud.tebibhost.com`) with the same credentials as the
`tebib` CLI.

Not released yet. Until it is, use it from a local build (see "Develop" below).

## Use

```hcl
terraform {
  required_providers {
    tebib = { source = "tebibhost/tebib" }
  }
}

provider "tebib" {}   # settings from TEBIB_* or your `tebib configure` profile
```

Settings, first match wins: the provider block, then `TEBIB_ENDPOINT`, `TEBIB_ACCESS_KEY_ID`,
`TEBIB_SECRET_ACCESS_KEY`, `TEBIB_ORGANIZATION`, `TEBIB_PROJECT`, `TEBIB_PROFILE`, then the CLI
profile files in `~/.config/tebib`, then the defaults. A full example (VPC, NAT gateway, VM,
volume, public IP, SSH key) is in [examples/complete](examples/complete/main.tf). The resource
docs are in [docs/](docs/), generated by `go generate`.

What it manages:

| Area | Resources | Data sources |
| --- | --- | --- |
| Projects | `tebib_project` | `tebib_project` |
| Network | `tebib_vpc`, `tebib_subnet`, `tebib_security_group`, `tebib_security_group_rule`, `tebib_nat_gateway`, `tebib_public_ip`, `tebib_public_ip_association` | `tebib_vpc`, `tebib_subnet`, `tebib_security_group` |
| Compute | `tebib_ssh_key`, `tebib_vm`, `tebib_volume`, `tebib_volume_attachment`, `tebib_snapshot` | `tebib_images`, `tebib_instance_types` |
| IAM | `tebib_iam_service_account`, `tebib_iam_access_key`, `tebib_iam_role`, `tebib_iam_policy`, `tebib_iam_policy_attachment`, `tebib_iam_group`, `tebib_iam_group_membership` | |
| Billing | | `tebib_prices` |

Add when merged (other Phase 7 work): object storage buckets and keys, snapshot schedules,
load balancers, DNS zones and records.

## How it works

- Auth: `Authorization: Bearer <key id>.<secret>`, as the CLI does. Role sessions (`TBS...`)
  work too.
- Asynchronous changes: the API answers 202 with `creating`, `updating` or `deleting`. The
  provider polls until the resource is `active` (or gone), within the `timeouts` block.
  A resource that ends in `error` stays in the state as tainted, so the next apply replaces it.
- Creates the API de-duplicates (project resources) send an `Idempotency-Key` and are retried
  on 502/503/504. IAM creates are sent once. Any call is retried on 429.
- Drift: every read refreshes from the API. Something deleted outside Terraform is removed
  from the state and made again.
- Known limits: the API never returns a VM's `user_data`, so it isn't refreshed. An access
  key's secret is only known when it is created, and it is stored in the state.

## Develop

Needs Go (see `go.mod`) and `terraform` or `tofu`.

```sh
go test ./...                 # unit tests: Terraform/OpenTofu against the fake API (internal/mockapi)
go generate ./...             # regenerate docs/ from the schema and examples/
go build -o ~/bin/terraform-provider-tebib .
```

To try a local build, point a CLI config at it (`TF_CLI_CONFIG_FILE`):

```hcl
provider_installation {
  dev_overrides { "tebibhost/tebib" = "/home/you/bin" }
  direct {}
}
```

Acceptance tests use a real endpoint and create billed resources:

```sh
TF_ACC=1 TEBIB_ACCESS_KEY_ID=... TEBIB_SECRET_ACCESS_KEY=... TEBIB_ORGANIZATION=o-... \
  TEBIB_PROJECT=p-... go test ./internal/provider -run TestAcc -timeout 60m
```

## Release

`.github/workflows/terraform-provider-release.yml` builds with goreleaser on a
`terraform-provider-v*` tag: zips per platform, `SHA256SUMS`, a GPG signature (registry rule)
and a cosign signature. It is not run yet; the registry namespace, the public repository and
the signing key are open questions in ADR 0042.
